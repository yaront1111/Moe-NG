# Recoverable replan handoff

The UI records a human REPLAN and then creates a source-bound successor. A missing source, lost response or reload must not silently strand that handoff or create duplicate goals.

1. Before REPLAN, validate the current goal, review, complete source, supported offers and final brief limits. Preserve the legacy header and add exact predecessor/node/review pins. Do not truncate received findings; the daemon independently reconstructs the complete durable review.
2. Capture both request identities and the exact draft before sending either command. Store only a bounded tab-local proposal scoped to project and origin. Retain no credentials and grant no authority from this journal.
3. Keep an incomplete handoff visible with an explicit resume action. Restore proposals after reload without sending commands. On resume, rejoin fresh source, catalog, approved run and exact node/review facts; reject conflicting or unreadable evidence.
4. Establish retirement from a correlated receipt or the exact next-version REPLANNED projection. Reuse the captured creation identity and payload, allowing renewed session authentication. First check the deterministic successor goal and exact source/brief to resolve a lost creation reply. Remove the proposal only after confirmed completion.
5. Test preparation failures before retirement, repeated clicks, both lost replies, reload and changed credentials, stale/foreign/corrupt evidence, exact existing-goal reconciliation and uncertain receipts. Exercise the production UI callback, shared builders and public read decoders. Run Control Room typecheck and its complete test suite.

Repository reservation recovery and complete server-side mission context are separate slices. Neither this UI proposal nor a creation retry accepts old work, waives criteria, revives a retry grant or approves the replacement plan.
