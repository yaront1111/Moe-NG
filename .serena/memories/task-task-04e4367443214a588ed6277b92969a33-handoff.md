## Design facts a follow-on needs
- The consumer port is `CoordinationRecipientRegistry = (address) => unknown` at
  `packages/coordination/src/coordination-ports.ts:35`, accepted by `isKnownRecipient` (:78):
  plain record, `Object.isFrozen`, own keys EXACTLY `["known","role"]`, `known===true`,
  `role===address.role`. `isKnownRecipient` is NOT exported from the package index.
- Aggregate: `moe.coordination-recipient.v1/recipient/<sessionId>`, one per session.
  Events: `CoordinationRecipientRegistered` / `Replaced` / `Revoked`. Revocation is TERMINAL.
- `effectId` is part of the registration identity. `coordination-service.ts:80-105` calls
  `resolveRecipient` on the whole address and checks the effect BINDING through a separate port.
- ROTATION: `readActiveSession` does NOT go absent after a rotation (session and credential
  generations bump together). The registry records the generation at write time and requires it
  to equal the current one. Without that, "rotated" is not a real branch. See
  `mem:gotcha-rotated-session-is-not-an-inactive-session`.
- Two negative answers, deliberately different values: frozen `{known:false, role:null}` means
  "looked, found nothing"; `undefined` means "never looked / unreadable".
- Idempotence: see `mem:gotcha-expectedversion-is-hashed-into-the-request-identity`.
