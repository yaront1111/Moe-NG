# Acceptance gates cannot classify absent capabilities as UNKNOWN

For acceptance/proof tasks, a PASS/FAIL/UNKNOWN matrix is a verdict vocabulary for evidence emitted by an existing production capability. It is not permission to retire an absent capability as an UNKNOWN row.

Before planning a matrix:
1. Probe the public production symbol and compiled dependency edge.
2. Find a real production caller/consumer, not only package tests.
3. Verify any required corpus or cross-host receipt exists and is generated from production bytes.
4. For packaged shells, verify the real artifact appears in the signed distribution inventory; a labelled fixture is not shipment.
5. For platform conformance, require the actual host. Off-host caller-supplied facts can test a classifier but cannot certify the OS.

If any subject is absent, create production prerequisites and block the acceptance task. Do not reimplement decoding/mapping/authority in the evidence harness, and do not call the missing subject UNKNOWN as if it had been observed.
