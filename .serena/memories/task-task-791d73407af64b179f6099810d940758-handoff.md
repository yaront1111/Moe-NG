## The rebuild driver's design, in one paragraph

`projections` stores a digest and a position but **never the state**, so a rebuild always
re-folds from global position 0 — that is what makes restart-mid-rebuild idempotent with no
schema change. Two-phase walk: while behind the durable checkpoint it writes nothing and
`clampPage` truncates each page so it can never step OVER that checkpoint; landing exactly on
it, the recomputed digest is compared against the stored `state_digest`; past it, every page
persists under the relay's byte-identical CAS. `expected` is threaded as *the rebuild's own
last written value*, not a per-transaction re-read — that is what makes a foreign advance lose
the CAS instead of being overwritten, and what keeps the WHERE clause load-bearing.
Signature gained an optional `state` origin (default `{}`); without it a rebuild cannot
reproduce a relay that started from a non-empty origin.

## Two real defects found by the drills and fixed here

1. **`projection-drill-test-helpers.ts` imported `sqlite-event-store-test-helpers.js`, which
   does not exist.** vitest and tsc silently resolve that back to the `.ts` sibling; plain
   Node does not. Every crash-worker spawn would have died at import instead of at its
   boundary. See `mem:gotcha-node-does-not-resolve-js-specifier-to-ts`.
2. **The walk broke on the UNCLAMPED page's `hasMore`.** With `pageLimit 100` over a ledger
   whose durable checkpoint sits mid-history, the source returns every event with
   `hasMore=false`, the clamp drops the tail, and the rebuild stopped at the checkpoint while
   returning `REBUILT` — a silent under-rebuild claiming completion. Found by writing the test
   that killed the one surviving mutant. Fix: break only when the clamp dropped nothing.

## One observation a follow-up may want, deliberately NOT called a defect

**The relay's own `PROJECTION_UPSERT` compare-and-set survives the entire 331-test suite when
neutralised to a tautology.** It is unreachable as the refusing layer by construction:
`requireProjectionAt` compares position and digest earlier in the SAME `BEGIN IMMEDIATE`, and
SQLite's single-writer lock means nothing can move the row in between. Defense in depth whose
outer layer always answers first — exactly the epic-rail-6 shape, but here the production code
is correct and no test can pin it without contriving a seam. Recorded rather than papered over
with a test that would only appear to cover it. The rebuild driver's CAS is different: its
persist transactions are separate per page, the race is reachable, and it is proven to bite.
