## Architecture decisions a reviewer will ask about

- **Ownership transfer requires a STRICT epoch advance plus a different token**, not
  `fenceMirroredLease` (which demands epoch equality — the wrong question for a transfer). A
  consequence worth knowing: a session re-adopting its OWN run at the same epoch is REFUSED. That
  is deliberate and fail-closed; after a crash the lease is SUSPECT and a fresh grant is required.
- **Ordering is the mechanism, in three places.** SUSPECT is answered before adoption; quarantine
  before absence; and in `advanceRecoveryDrain` the recovery downgrade/drop checks run BEFORE the
  supervisor's `isMonotonicDisposition`. That last one matters: under the reverse order the
  supervisor would always answer first and `RECOVERY_DRAIN_DOWNGRADE_REFUSED` could never be
  produced at all.
- **The ABSENT branch does not re-test `resourceFact === "PROVEN_RELEASED"`** — the quarantine gate
  above it already guarantees it, and adding the conjunct would create an operand no test can
  redden. Drill R7 confirms the gate is load-bearing (5 tests red when neutralised).
- **`RECOVERY_PROPOSED_COMMANDS` was written and then removed.** It used
  `.filter(k => RUNTIME_COMMAND_KINDS.includes(k))`, which fails OPEN — a drifted command would
  silently vanish and the export would still look healthy. The `RuntimeCommandKind` type annotation
  already fails the build on drift.
