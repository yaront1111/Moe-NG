## The three dispositions — read this before extending

```ts
FairnessContractResult<T> =
  | { ok: true; value: T }
  | { ok: false; disposition: "REFUSED" | "UNKNOWN"; issues: readonly FairnessContractIssue[] }
```
`issue.missingInput` is non-null **exactly** on UNKNOWN, and `unknownFairness()` takes it
as a REQUIRED parameter, so an unnamed UNKNOWN is unconstructible. A test asserts the
biconditional across the whole reachability table.

Validators return **exactly one issue**, the first violation in a documented field order.
Do not "improve" this into accumulation without changing the tests: every assertion is
whole-object `toEqual([{code, layer}])`, which is what caught drill 1a.

## What NOT to copy from `packages/testkit/src/scheduler-fairness` (DEVELOPMENT_ONLY)

Measured, not assumed:
- `fairness-codec.ts:71,83-84` decodes `bypassesInLevel` from caller input and
  range-checks it only. A range check is not a proof.
- `FairnessTicket.dispatchable` is a bare boolean documented "caller-confirmed" — an

- `isFairnessId` accepts any well-formed Unicode to 256 UTF-8 bytes, so invisible and

- No ring / WDRR / deficit / resourceQueue vocabulary exists there at all. The grep that
  "finds" it is matching the substring `ring` inside the word **string**.
