# Decision: five presentation trust boundaries in one capped plan

After the epic rail clarified that the cap is per file rather than summed task LOC, archive the earlier child tasks and implement the node/attempt workspace in one 10-file plan. Keep five independent component/test pairs so every production and test module remains <=250 lines:
1. node authority/plan;
2. node input/result/context/recovery;
3. receipts/artifacts/findings/blockers;
4. attempt operational history with collapsed transcript;
5. clean review firewall.

These are local presentation prop contracts, not daemon response DTOs. No route, fetch, authority calculation, or secret-bearing lease object is allowed. The clean-review exclusion boundary remains structural at both TypeScript prop and DOM levels.
