## Design decisions a reviewer will challenge

- **Opaque refs, per `mem:decision-runner-cannot-import-store-or-daemon`.** Backup cursor and
  recovery incarnation enter as `{kind, ref, digest}`, validated and digest-bound, never
  interpreted. No new dependency: `@moe/runner` still needs only `@moe/contracts`.
- **One proof per CONFIGURED class, never per returned class.** No registration -> UNKNOWN /
  `ENUMERATOR_UNREGISTERED`, not absent. Aggregate COMPLETE also requires
  `proofs.length === configuredClasses.length` and non-empty — `every()` on an empty list is true.
- **Item refusals carry their OWN code** (`CLASS_MISMATCH`, `PROJECT_MISMATCH`,
  `WINDOW_MISMATCH`, `EXTERNAL_IDENTITY_DUPLICATE`) with reason `ITEM_REJECTED`; enumerator-level
  problems get `COVERAGE_UNKNOWN`. Two different vocabularies on purpose.
- **PATH identities are separator-normalized; OPAQUE ones are NOT.** Both directions are pinned,
  which is what stops a blanket backslash rewrite from merging distinct provider ids.
- **`utcSortKey`** exists because `...:00Z` and `...:00.000Z` are the same instant but `.` sorts
  below `Z`, so a lexicographic window bound silently excludes an edge observation.
- Registry is an immutable caller-supplied tuple. Sibling slices export registry FRAGMENTS and the
  daemon composes them — **their descriptions say to edit this aggregate; that wording is stale.**
