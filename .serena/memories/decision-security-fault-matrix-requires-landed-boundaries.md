# Decision: a security/fault matrix cannot precede the production boundary registry it certifies

For a proof task whose DoD is exhaustive across authority/effect boundaries, the case universe must be derived from landed production entry points and frozen protocol registries, not from the design alone or a test helper's hand-written approximation.

Planning is blocked when any of these holds:
- a named transport/provider/IDE/import/force/platform boundary is absent or not QA-approved;
- composed command/recovery authority is still pure or in flight;
- the task's exact gate command does not exist within an owned prerequisite;
- another live task owns part of the fixture tree;
- a supported-host claim would be produced off-host without a real runner.

The valid unblock is to land the subjects and the typed test lanes first. After that, each hostile/refusal row must assert its stable reason code and refusing layer, each generated sweep must assert its non-zero and complete case universe, and unobservable host behavior must remain UNKNOWN or explicitly outside scope. A fixture-only journey that proves only shapes is not evidence of the production system.
