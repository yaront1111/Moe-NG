# Provider-run codec design-review handoff

Read-only review of provider-run-codec.test.ts, provider-run-contracts.ts,
provider-run-refusals.ts, and activation-ledger-codec.ts.

## Exact format and guard split
Use `UTF8(recordVersion + "\n") || u32be(body.length) || body ||
u32be(64) || ASCII(lowercaseSha256)`. The body is sorted-key canonical JSON of
the record after replacing caller `recordDigest` with the computed digest.
The digest domain is sorted-key canonical JSON of the same value with
`recordDigest` excluded.

Decode must validate exact header/framing and parse fatally, re-encode the parsed
value, compare the recomputed digest to the carried tail (guard A), and compare
only the canonical BODY bytes to the received body (guard B). Comparing the
entire sealed result would make a tail-only digest mutation get caught by B and
would make the mandatory guard-A mutation drill vacuous.

## Exact refusals
Encode: non-plain top level -> REFUSED/RECORD_MALFORMED; unsupported version ->
REFUSED/VERSION_UNSUPPORTED; undefined, sparse arrays, nonfinite numbers, cycles,
unsafe JSON values, or oversize -> REFUSED/FIELD_INVALID.
Decode: invalid input/framing/UTF-8/JSON/truncation -> UNKNOWN/BYTES_MALFORMED;
parsed non-record -> UNKNOWN/RECORD_UNREADABLE; header/body version mismatch ->
UNKNOWN/VERSION_UNSUPPORTED; either verification guard -> UNKNOWN/DIGEST_MISMATCH.
All use imported PROVIDER_RUN_CODEC and null storeCode.

## Inconsistencies / cautions
- The test deletes required ProviderRunRecord.observedEnd and requires encode
  success. Together with the ban on a local field list and absence of a
  contract-owned runtime guard, a codec cannot genuinely narrow unknown to
  ProviderRunRecord. A version-only plain object is accepted by the current
  design. This is a plan/test type-safety contradiction.
- Plan wording says re-encode and compare all bytes, but guard independence
  requires comparing canonical body bytes only; header/framing/tail have their
  own guards.
- DoD wording says digest over the bytes/frozen bytes. Hashing received bytes
  would subsume guard B, and nonempty Uint8Array cannot be Object.freeze'd.
  Interpret this as a frozen result envelope plus digest over reconstructed
  canonical reduced-value bytes.
- Contrary to the step-2 note that every failure pins code/layer/outcome, tests
  for nested array holes, NaN/Infinity, truncation, and body-version mismatch
  omit the layer assertion.
- For containment, wrap decode of hostile Uint8Array subclasses/proxies; snapshot
  canonical reduced JSON before the second traversal/return so caller aliases
  cannot mutate the returned record away from its bytes.
