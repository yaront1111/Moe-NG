## The fix pattern (reusable)

Each case hands the upstream **production returned** to a collector BEFORE
pinning it, and the closing test reads that collector:

```ts
type ObservedUpstream = RecoveryInventoryRefusal["upstream"] | RecoveryCompletionUpstream;
const observedUpstreams = new Map<string, ObservedUpstream>();
// in each case, BEFORE the toEqual pin:
observeUpstream("case 1: absent inventory", read.upstream);
```

Three details that carry the weight:

1. **Observe BEFORE the per-case pin.** Otherwise a collapse trips the per-case
   `toEqual` first, the case aborts, the map is short, and the failure reads as
   an under-swept set instead of as a distinctness violation.
2. **Derive the type, never restate `{ code, layer }`.** A hand-written shape is
   the same defect class being fixed. `RecoveryInventoryRefusal` and
   `RecoveryCompletionUpstream` are both on the `@moe/daemon` ROOT;
   `RecoveryInventoryUpstream` is NOT exported and adding it would be an
   out-of-scope production change.
3. **Refuse a null upstream, do not skip it.** `readRecoveryCompletionEvidence`
   returns `RecoveryCompletionUpstream | null` (tsc catches this). Skipping null
   would silently shrink the set into a vacuous pass.

Assert `size === 3` (the sweep swept) separately from distinctness, and compare
distinctness against `observed.length` not the literal 3 — that keeps the two
guards discriminating instead of covering for each other.
